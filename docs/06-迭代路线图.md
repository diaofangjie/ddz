# 06 - 迭代路线图

> 策略：**不重写，做外科手术式重构。**
> 理由：项目已有 10+ 项自研玩法（癞子、加倍、弃牌、2v2 队伍、托管、重连、记牌器、PWA、APK）。
> 重写意味着这些细节要重新踩一遍坑，而收益只有"代码看起来更干净"。**不划算。**

> 每一步都有独立的、可验证的产出；任何一步都可单独停下而不留半成品。

## 阶段 3 — 在线能力（用户的核心诉求）

**目标**：稳定支持"好友房间、最多 10 人、三/四人斗地主"的实时对战。

| # | 任务 | 交付物 | 验收 |
|---|------|--------|------|
| 3.1 | **HTTPS + 域名** | Nginx TLS 终结、80→443 跳转、`/socket.io` 反代 | 浏览器无混合内容告警；微信内可正常打开 |
| 3.2 | 同域相对路径 | 前端 `io()` 不再依赖 IP，删除 `config.js` 硬编码 | 换域名零代码改动 |
| 3.3 | 房间容量模型 | 座位（3/4）+ 观战席，总容量 10 | 满员后加入者进观战席，且**看不到任何手牌** |
| 3.4 | 观战与轮换 | `room:takeSeat` / `room:leaveSeat`（仅局间） | 对局中不可入座 |
| 3.5 | 持久化 | 快照 + 对局历史落 SQLite | `pm2 restart` 后房间可恢复 |
| 3.6 | 重连强化 | `sessionToken` 恢复；重连后状态与断线前逐字段一致 | P-06 通过 |
| 3.7 | 托管策略固化 | 超时/离线判定与交还规则 | 不死锁（B-5 已修） |
| 3.8 | 回合计时统一 | 服务端下绝对时间戳，客户端算剩余 | 各端倒计时一致（±0.5s） |
| 3.9 | 连接健壮性 | 心跳、重连退避、错误码提示 | 弱网下不出现"幽灵玩家" |
| 3.10 | 安全加固 | CORS 收紧、限流（聊天/建房）、22 端口限源、禁密码登录 | `00-现状审计` P2 项清零 |

**主机选型决策（阶段 3 内必须做）**：
试用到期后有三个方向，需在 **到期前 2 周**决定：

| 方案 | 成本 | 优点 | 缺点 |
|------|------|------|------|
| A. 续费国内轻量应用服务器 | ~¥60-100/月 | 延迟低、备案透明 | 需域名备案（国内节点） |
| B. 香港/新加坡轻量实例 | ~¥25-35/月 | **免备案**、可立即上 HTTPS | 国内访问延迟略高 |
| C. 平台化（Vercel 前端 + 托管 WS 服务） | 低 | 免运维 | 实时后端受限，不推荐 |

> 建议 **B**：好友娱乐场景下免备案带来的速度优势，远大于几十毫秒延迟差异。
