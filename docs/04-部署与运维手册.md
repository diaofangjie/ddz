## 2. 系统拓扑（当前）

```
公网
 ├─ :80  ──► Nginx ──► /root/ddz/client/build  (静态站点)
 └─ :3001 ──► Node/pm2 (ddz-server)  ──► Socket.IO 实时对战
                └─ 顺带托管 client/build（冗余路径，建议关闭）
```

---

## 3. 系统拓扑（目标态）

```
公网
 └─ :443 ──► Nginx (TLS 终结, Let's Encrypt)
              ├─ location /            → 静态站点 client/build
              ├─ location /socket.io/  → proxy_pass http://127.0.0.1:3001
              └─ location /health      → proxy_pass http://127.0.0.1:3001
        :80  ──► 301 永久跳转到 https
        :3001 ──► 仅监听 127.0.0.1（不对公网开放，减少攻击面）
```

**收益**：前端 `io()` 走同域相对路径 → **彻底删掉硬编码 IP（P1-8）**；换 IP、上域名零代码改动；消除 Node 直连公网的攻击面。

### 容量评估（预判）

| 维度 | 判断 |
|------|------|
| CPU / 内存 | 阿里云免费试用实例通常 2 核 2G 或 2 核 4G。**Socket.IO + 10 人房间 完全不是瓶颈** |
| 真实瓶颈 | ①`npm run build` 在前端构建时吃内存（2G 实例上 CRA 构建可能 OOM → 需在本地构建后上传 `build/`）；②无 HTTPS；③无持久化 |
| 并发估算 | 假设 20 个房间 × 10 人 = 200 个并发连接。Socket.IO 单进程处理 200 连接属于低负载（通常单进程可支撑数千连接） |
| 结论 | **当前服务器规格足以支撑目标需求，无需升配**。要优化的是"工程完备性"，不是"算力" |

### 5.2 发布（推荐：本地构建 + 上传产物）

### 5.3 pm2 常驻

```bash

```

**pm2 关键配置建议**（`ecosystem.config.js`）：

```js

    name: 'ddz-server',
    script: 'src/index.js',
    instances: 1,              // ⚠️ 必须单实例：房间状态在进程内存
    max_memory_restart: '600M',
    env: { NODE_ENV: 'production', PORT: 3001 },
    error_file: '/var/log/ddz/error.log',
    out_file: '/var/log/ddz/out.log',
    time: true
  }]

```

### 5.4 Nginx + HTTPS

```bash
apt install -y certbot python3-certbot-nginx
```

```nginx
# /etc/nginx/sites-available/ddz
server {
    listen 80;
    server_name your-domain.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name your-domain.com;

    ssl_certificate     /etc/letsencrypt/live/your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;

    root /srv/ddz/client/build;
    index index.html;

    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;

    # 静态资源长缓存（CRA 产物带 hash）
    location /static/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    location / {
        try_files $uri $uri/ /index.html;   # SPA 回退
    }

    location /socket.io/ {
        proxy_pass http://127.0.0.1:3001;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;     # WebSocket 必需
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_read_timeout 300s;                    # 长连接不要被切断
    }

    location /health {
        proxy_pass http://127.0.0.1:3001;
    }
}
```

```bash
ln -s /etc/nginx/sites-available/ddz /etc/nginx/sites-enabled/ddz
rm -f /etc/nginx/sites-enabled/default
nginx -t && systemctl reload nginx
certbot --nginx -d your-domain.com     # 自动申请并续期
```

> 🔴 **无域名怎么办**：只能用 IP + 自签证书，浏览器/微信会告警或直接拦截，**应用内 API（通知、剪贴板、部分媒体能力）在非 HTTPS 下不可用**。
> **强烈建议申请一个域名**（或使用已有域名的一个子域，如 `ddz.example.com`）。这是本次优化中**性价比最高**的一步。

### 5.5 安全组（阿里云控制台）

| 端口 | 来源 | 说明 |
|------|------|------|
| 22 | **你的固定 IP/32** | ❌ 不要 `0.0.0.0/0` |
| 80 | `0.0.0.0/0` | ACME 校验 + 跳转 |
| 443 | `0.0.0.0/0` | 对外服务 |
| 3001 | **关闭公网** | 仅 `127.0.0.1` 监听，由 Nginx 反代 |

服务器侧同步：

```bash
# 禁止 Node 直接暴露公网（代码里改为 listen(3001, '127.0.0.1')）
# 密码登录改为密钥登录
sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
systemctl restart sshd
apt install -y fail2ban && systemctl enable --now fail2ban
```

### 6.2 备份策略（好友规模，够用即可）

```bash
# /srv/ddz/scripts/backup.sh
#!/usr/bin/env bash
set -euo pipefail
D=/srv/ddz/data
B=/srv/ddz/backup
mkdir -p "$B"
tar -czf "$B/ddz-$(date +%F-%H%M).tgz" -C "$D" .
find "$B" -name 'ddz-*.tgz' -mtime +14 -delete   # 保留 14 天
```

```bash
chmod +x /srv/ddz/scripts/backup.sh
# 每天 04:00 备份
( crontab -l 2>/dev/null; echo "0 4 * * * /srv/ddz/scripts/backup.sh" ) | crontab -
```

> **必须做**：①设置到期提醒（提前 7 天）；②备份异地保存（本机 `D:\dfj\dfj\ddz\backup\` 或对象存储）。

## 8. 监控与排障

### 8.1 常用命令

```bash
pm2 status
pm2 logs ddz-server --lines 100
pm2 monit
tail -f /var/log/nginx/access.log
tail -f /var/log/nginx/error.log
ss -tulnp | grep 3001
```

### 8.2 排障速查表

| 现象 | 首要排查 |
|------|----------|
| 前端打不开 | Nginx 是否运行；`/srv/ddz/client/build/index.html` 是否存在 |
| 能打开但连不上房间 | `curl /health`；Nginx 的 `/socket.io/` 反代是否带 `Upgrade` 头 |
| 手机能开但一直"连接中" | 是否 HTTPS；混合内容被浏览器拦截（控制台会有 Mixed Content 警告） |
| 页面卡在旧版本 | 静态资源缓存 → 强制刷新，或检查 `index.html` 的 `Cache-Control`（**`index.html` 必须不缓存**） |
| 掉线后无法重连 | 房间是否已被清理；`sessionToken` 是否丢失（localStorage 被清） |
| 服务器重启后牌局全丢 | 正常现象（P0-6 未修）→ 按阶段 3 实现快照 |
| 内存持续增长 | `pm2 monit` 看内存曲线；检查 `turnTimers` / `roundReadyTimers` 是否泄漏（`startTurnTimer` 只在 `clearTurnTimer` 时删除，房间销毁路径需确认清理） |
| 玩家反馈"牌不对/别人能看见我牌" | 立即按 P0-2 处理：检查是否有裸 `emit(currentRoom)` 路径 |

### 8.3 最小告警（可选，低成本）

用 crontab 每 5 分钟探活，失败时写日志（后续可接邮件）。

```bash
# /srv/ddz/scripts/watchdog.sh
#!/usr/bin/env bash
if ! curl -sf -m 5 http://127.0.0.1:3001/health > /dev/null; then
  echo "$(date -Is) ddz-server DOWN" >> /srv/ddz/data/logs/watchdog.log
  pm2 restart ddz-server
fi
```

```bash
( crontab -l 2>/dev/null; echo "*/5 * * * * /srv/ddz/scripts/watchdog.sh" ) | crontab -
```

## 9. 环境变量清单（目标态）

代码中**不允许**出现硬编码 IP / 端口 / 密钥。统一由环境变量注入：

| 变量 | 默认 | 说明 |
|------|------|------|
| `PORT` | `3001` | 服务端口 |
| `HOST` | `127.0.0.1` | 生产环境只监听回环（由 Nginx 反代） |
| `NODE_ENV` | `production` | |
| `CORS_ORIGIN` | `same-origin` | 🎯 由 `*` 收紧为具体域名 |
| `TURN_TIME_LIMIT` | `20` | 默认回合计时（秒） |
| `SNAPSHOT_INTERVAL_MS` | `30000` | 快照间隔 |
| `ROOM_CAPACITY` | `10` | 房间总容量（座位 + 观战席） |
| `LOG_LEVEL` | `info` | |
