# ADR — 架构决策记录

> ADR（Architecture Decision Record）记录**"为什么这么做"**。
> 代码记录"做了什么"，git 记录"什么时候改的"，只有 ADR 记录"当时为什么这样选、放弃了什么"。

## 什么时候写 ADR

满足**任一**条件就写：

- 技术选型（框架、库、协议、存储、部署方式）
- 接口/数据结构发生**破坏性变更**
- 做出了一个"以后改起来会很贵"的决定
- 放弃了一个看起来更显然的方案（并需要解释原因）

不写 ADR：普通功能开发、局部重构、bug 修复。

## 状态

| 状态 | 含义 |
|------|------|
| `提议中` | 已提出，尚未实施，欢迎推翻 |
| `已采纳` | 正在生效 |
| `已弃用` | 曾生效，现已被取代（标注取代它的 ADR 编号） |
| `已驳回` | 讨论后决定不采用（保留记录，避免后人重复提议） |

**ADR 一旦采纳就不再修改内容**。要改变决定，就新写一条并标注取代关系。

- **取代**：（可选）被本 ADR 取代的编号
