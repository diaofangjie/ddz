# 05 - 测试与质量保障

> 原则：**先有网，再拆房。**
> 当前代码 1881 行后端 + 约 2000 行的 `GameScreen.js`，**零自动化测试**。在这个状态下动重构 = 赌运气。
> 因此测试建设是**阶段 1 的唯一目标**，也是阶段 2 重构的前置条件。

---

## 1. 测试分层

```
        ▲  少而慢
   E2E（socket 多客户端全流程）
        │   · 3 人局 / 4 人局 完整对局
        │   · 断线重连 / 超时托管
        │   ~15 个场景
        ├────────────────────────────────
   集成（房间生命周期 + 投影）
        │   · RoomManager + projector + scheduler 组合
        │   · 协议断言 P-01 ~ P-08
        │   ~30 个用例
        ├────────────────────────────────
   单元（domain 纯逻辑）★ 重点 ★
        │   · 牌型识别 / 比较 / 计分 / 状态机转移
        │   · 快、稳、覆盖高 → 目标 200+ 用例
        ▼  多而快
```

**投入产出比**：`domain/` 的单测成本最低、收益最高 —— 因为它是纯函数，不需要 socket、不需要计时器、不需要数据库。

## 4. 协议断言（集成层）

见 `02-通信协议规范.md` 第 4 节的 **P-01 ~ P-08**。这些是**重构期间最重要的回归防线**，尤其是：

- **P-01**：任一客户端收到的状态里带 `hand` 的座位恒为 1 个 → 手牌泄露一旦回归立即红。
- **P-04**：同房间所有客户端收到同一 `rev` → 广播分叉回归立即红。
- **P-06**：断线重连后手牌逐张一致 → 重连逻辑回归立即红。

### 4.1 E2E 骨架（可直接落地）

```js
// server/test/e2e/three-players.spec.js
import { describe, it, expect, beforeAll, afterAll } from 'vitest';
import { io } from 'socket.io-client';

const URL = process.env.TEST_URL || 'http://localhost:3001';
const connect = () => new Promise((res) => {
  const s = io(URL, { transports: ['websocket'], forceNew: true });
  s.on('connect', () => res(s));
});

describe('3 人局全流程', () => {
  let clients;
  beforeAll(async () => { clients = await Promise.all([connect(), connect(), connect()]); });
  afterAll(() => clients.forEach((c) => c.close()));

  it('P-01 每人只能看到自己的手牌', async () => {
    const states = await runUntil(clients, 'playing');
    for (const st of states) {
      const seatsWithHand = st.seats.filter((s) => Array.isArray(s.hand));
      expect(seatsWithHand).toHaveLength(1);
    }
  });
});
```

### 5.2 重构安全网标准

进入阶段 2（架构重构）**必须满足**：

| 门槛 | 要求 |
|------|------|
| `domain/` 单测 | ≥ 200 个用例，全部通过 |
| 覆盖率 | `domain/` 行覆盖 ≥ 90% |
| 协议断言 | P-01 / P-04 / P-06 / P-08 全绿 |
| E2E | 3 人局、4 人局各至少 1 条完整对局通过 |

### 5.3 每次改动的自查清单

- [ ] 新增/修改的业务规则，是否有对应用例？
- [ ] 用例是否**先失败后通过**（真实验证过）？
- [ ] 是否覆盖了边界：空手牌、只剩 1 张、最后一手、全员 pass、超时、断线？
- [ ] `sum(scores) === 0` 的守恒断言是否仍通过？
- [ ] 是否引入了新的 `Math.random()` 或 `Date.now()` 直接调用？（应通过注入以便测试）
