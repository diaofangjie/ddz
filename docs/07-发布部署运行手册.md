> ## 🔴 2026-09-16 重大更正：线上真实路径与本手册不符
>
> 本手册早期版本依据 `ALIYUN_DEPLOY.md` 推测线上结构为 `/root/ddz`，**推测错误**。
> 完成真实部署后用 SSH 实测到的事实是：
>
> | 项目 | 手册早期写的 | **实测真实值** |
> |------|-------------|---------------|
> | 项目根 | `/root/ddz` | **`/root`**（没有 `ddz` 这一层） |
> | 后端源码 | `/root/ddz/server/src` | **`/root/server/src`** |
> | 后端 cwd | `/root/ddz/server` | **`/root/server`** |
> | 前端产物 | `/root/ddz/client/build` | **`/var/www/ddz`**（nginx root） |
> | Node 静态目录 | — | **`/root/client/build`**（第二份前端，必须同步） |
> | nginx 配置 | `/etc/nginx/sites-available/default` | 一致 ✓ |
> | pm2 应用名 | `ddz-server` | 一致 ✓ |
>
> **⚠️ 前端有两份，别只更新一份**：
> - `:80` 由 nginx 提供 → 读 `/var/www/ddz`
> - `:3001` 由 Node 的 `express.static('../../client/build')` 提供 → 读 `/root/client/build`
>
> 两个入口都指向 `/`，只更新其中一个会出现"从 80 端口进来是新版、从 3001 进来是旧版"。
>
> ---
>
> ### 另发现一个既有缺陷（本次已修）
>
> 原 `server/src/index.js` 把 SPA 兜底路由注册在了所有业务路由**之前**：
>
> ```js
> app.use(express.static(...));      // 第 14 行
> app.get('*', ...sendFile(index.html));  // 第 16 行  ← 通配符
> ...
> app.get('/health', ...)           // 第 442 行 ← 永远执行不到
> ```
>
> 后果：`/health` 被通配符吃掉，永远返回 `index.html` 而不是 `{"status":"ok"}`，
> 导致**任何健康检查／存活探针失效**（这也是为什么早期实测 `:3001/health` 看起来是正常的，
> 实际上当时那台机器跑的是更老的、路由顺序正确的版本）。
>
> 修法：把 `app.get('*')` 移到文件末尾、`server.listen` 之前。
> 已加注释提醒后来者不要提前。
>

## 0. 本次发布要解决什么问题

线上 `8.137.195.155` 跑的还是**修复前**的代码，存在三个可作弊漏洞和一个卡死 bug：

| 编号 | 线上现状 | 本次修复 |
|------|----------|----------|
| P0-2 | 服务端把**所有人手牌**广播给全房间，开 F12 就能看牌 | 按观察者逐人裁剪，他人手牌改为等长占位牌 |
| P0-3 | 动作事件采信客户端自报的 `playerId`，可替别人出牌 | 身份改由服务端与 socket 强绑定 |
| **P0-4** | `playerId` 会广播给全场，且"id 命中即当重连"→ **同房间任何人都能顶替他人座位、看光对方手牌** | 身份由服务端签发，重连必须出示不可猜测的 `sessionToken` |
| BUG-1 | AI/离线托管遇到压不过的牌会抛错，**整局卡死** | `pickBomb()` 统一校验，压不过则过牌 |

> ⚠️ 也就是说：**在完成本次部署之前，任何玩家都能作弊，且双副牌局有一定概率卡死。** 建议尽快上线。

> 🔴 **本次是协议变更，必须前后端一起部署**：
> 服务端开始签发 `sessionToken`，前端也要提交它才能重连。
> **只更新一边会导致玩家刷新页面后无法回到原座位。**
> 请务必按第 3.3 步同时替换 `server/src` 和 `client/build`。

## 3. 方案 A：本地构建打包上传（推荐）

> **为什么推荐**：阿里云国内节点访问 GitHub 经常超时；且 `client/build` 不在 git 里，`git pull` 根本拿不到前端产物。

### 3.1 本地：构建 + 打包

在 **Windows 本地** `D:\dfj\dfj\ddz` 下执行：

```bash
# ① 构建前端（关键：必须先清掉 CI 变量，否则 lint 警告会被当成错误导致构建失败）
cd /d/dfj/dfj/ddz/client
unset CI
npx react-scripts build          # 预期输出：Compiled with warnings.  ← 有 warnings 是正常的

# ② 回项目根目录，打包发布件
cd /d/dfj/dfj/ddz
tar -czf ddz-release.tgz client/build server/src server/package.json server/package-lock.json
ls -lh ddz-release.tgz
```

> ✅ 打包结果约几 MB，**不含 `node_modules`**（跨平台二进制不兼容，传上去也没用）。

### 3.2 上传到服务器

任选一种：

```bash
# 方式一：有 SSH 密钥/scp 权限时
scp ddz-release.tgz root@8.137.195.155:/root/

# 方式二：阿里云控制台
# ECS 控制台 → 实例 → 远程连接 → 文件上传，把 tgz 传到 /root/
```

### 3.3 服务器：备份 → 替换 → 重启

用 SSH 或阿里云网页终端登录服务器后执行：

```bash
cd /root

# ① 备份（出错可秒回滚，别跳过）
cp -a ddz ddz.bak.$(date +%Y%m%d%H%M)
ls -d ddz.bak.* | tail -3

# ② 解包覆盖（-C /root/ddz 表示解到项目目录，会覆盖 client/build 与 server/src）
tar -xzf ddz-release.tgz -C /root/ddz

# ③ 确认源码确实更新了（应能看到 projectGame / authorize 这些新函数名）
grep -c "projectGame\|emitPerViewer" /root/ddz/server/src/index.js
grep -c "pickBomb" /root/ddz/server/src/GameLogic.js
# 两个数字都应 > 0；若为 0 说明没解包成功

# ④ 重启后端（重启会断开所有在线连接，请挑没人在打牌的时候做）
pm2 restart ddz-server
pm2 status
```

> 🔸 只有在 `server/package.json` 或 `package-lock.json` 发生变化时，才需要额外执行：
> ```bash
> cd /root/ddz/server && npm install --omit=dev
> ```
> 本次发布**没有**改依赖，可以跳过。

### 3.4 让 Nginx 吐出新的前端

Nginx 直接读磁盘上的 `client/build`，**不需要 reload**。但为了让用户拿到新 bundle，建议确认一下：

```bash
ls -l /root/ddz/client/build/static/js/          # 应有新的 main.<hash>.js
```

浏览器端因为 `index.html` 引用的是带 hash 的新文件名，用户刷新即生效（旧缓存不会命中）。
