## 0. 本次发布要解决什么问题

线上 `8.137.195.155` 跑的还是**修复前**的代码，存在三个可作弊漏洞和一个卡死 bug：

| 编号 | 线上现状 | 本次修复 |
|------|----------|----------|
| P0-2 | 服务端把**所有人手牌**广播给全房间，开 F12 就能看牌 | 按观察者逐人裁剪，他人手牌改为等长占位牌 |
| P0-3 | 动作事件采信客户端自报的 `playerId`，可替别人出牌 | 身份改由服务端与 socket 强绑定 |
| **P0-4** | `playerId` 会广播给全场，且"id 命中即当重连"→ **同房间任何人都能顶替他人座位、看光对方手牌** | 身份由服务端签发，重连必须出示不可猜测的 `sessionToken` |
| BUG-1 | AI/离线托管遇到压不过的牌会抛错，**整局卡死** | `pickBomb()` 统一校验，压不过则过牌 |

> ⚠️ 也就是说：**在完成本次部署之前，任何玩家都能作弊，且双副牌局有一定概率卡死。** 建议尽快上线。

> 🔴 **本次是协议变更，必须前后端一起部署**：
> 服务端开始签发 `sessionToken`，前端也要提交它才能重连。
> **只更新一边会导致玩家刷新页面后无法回到原座位。**
> 请务必按第 3.3 步同时替换 `server/src` 和 `client/build`。

## 3. 方案 A：本地构建打包上传（推荐）

> **为什么推荐**：阿里云国内节点访问 GitHub 经常超时；且 `client/build` 不在 git 里，`git pull` 根本拿不到前端产物。

### 3.1 本地：构建 + 打包

在 **Windows 本地** `D:\dfj\dfj\ddz` 下执行：

```bash
# ① 构建前端（关键：必须先清掉 CI 变量，否则 lint 警告会被当成错误导致构建失败）
cd /d/dfj/dfj/ddz/client
unset CI
npx react-scripts build          # 预期输出：Compiled with warnings.  ← 有 warnings 是正常的

# ② 回项目根目录，打包发布件
cd /d/dfj/dfj/ddz
tar -czf ddz-release.tgz client/build server/src server/package.json server/package-lock.json
ls -lh ddz-release.tgz
```

> ✅ 打包结果约几 MB，**不含 `node_modules`**（跨平台二进制不兼容，传上去也没用）。

### 3.2 上传到服务器

任选一种：

```bash
# 方式一：有 SSH 密钥/scp 权限时
scp ddz-release.tgz root@8.137.195.155:/root/

# 方式二：阿里云控制台
# ECS 控制台 → 实例 → 远程连接 → 文件上传，把 tgz 传到 /root/
```

### 3.3 服务器：备份 → 替换 → 重启

用 SSH 或阿里云网页终端登录服务器后执行：

```bash
cd /root

# ① 备份（出错可秒回滚，别跳过）
cp -a ddz ddz.bak.$(date +%Y%m%d%H%M)
ls -d ddz.bak.* | tail -3

# ② 解包覆盖（-C /root/ddz 表示解到项目目录，会覆盖 client/build 与 server/src）
tar -xzf ddz-release.tgz -C /root/ddz

# ③ 确认源码确实更新了（应能看到 projectGame / authorize 这些新函数名）
grep -c "projectGame\|emitPerViewer" /root/ddz/server/src/index.js
grep -c "pickBomb" /root/ddz/server/src/GameLogic.js
# 两个数字都应 > 0；若为 0 说明没解包成功

# ④ 重启后端（重启会断开所有在线连接，请挑没人在打牌的时候做）
pm2 restart ddz-server
pm2 status
```

> 🔸 只有在 `server/package.json` 或 `package-lock.json` 发生变化时，才需要额外执行：
> ```bash
> cd /root/ddz/server && npm install --omit=dev
> ```
> 本次发布**没有**改依赖，可以跳过。

### 3.4 让 Nginx 吐出新的前端

Nginx 直接读磁盘上的 `client/build`，**不需要 reload**。但为了让用户拿到新 bundle，建议确认一下：

```bash
ls -l /root/ddz/client/build/static/js/          # 应有新的 main.<hash>.js
```

浏览器端因为 `index.html` 引用的是带 hash 的新文件名，用户刷新即生效（旧缓存不会命中）。

## 4. 方案 B：服务器直接拉 GitHub（仅当服务器能访问 GitHub 时）

```bash
cd /root/ddz
git rev-parse --short HEAD                        # 先看当前停在哪个提交
git pull origin main                              # 需要服务器能访问 GitHub

# 前端产物不在 git 里，必须在服务器上构建，或仍走方案 A 传 build
cd /root/ddz/client
npm install --omit=dev                            # 首次才需要
unset CI
npx react-scripts build                           # ⚠️ 2G 内存实例上 CRA 构建可能 OOM

cd /root/ddz/server
npm install --omit=dev                            # 依赖有变化时才需要
pm2 restart ddz-server
```

**如果 `git pull` 卡住/超时** → 放弃方案 B，回到方案 A。
**如果 `npm run build` 被 OOM Killer 杀掉** → 只能在本地构建后传 `build/`（回到方案 A）。

### 5.3 🔒 安全修复验证（本次重点，务必做）

在**玩家 A** 的浏览器里：

1. 按 `F12` → 切到 **Network（网络）** → 过滤 **WS**
2. 点开 socket.io 的连接 → 看 **Messages（消息）** 帧
3. 找到 `roomUpdated` / `gameUpdated` 事件，展开它的 `game.hands`

**期望看到**：

```jsonc

  [ /* 你自己的真实手牌，有 rank/suit */ ],          // ← 只有你这一份是真实的
  [ {"rank":"hidden","suit":"hidden","isHidden":true}, ... ],  // ← 别人是占位牌
```

**如果看到别人的真实牌面（有 `rank:"A"` 之类） → 说明部署没生效，检查第 3.3 步的 grep 结果。**

### 5.4 🔑 会话令牌验证（P0-4，本次重点）

**A. 合法重连（必须能用）**

1. 玩家 A 进入房间并开一局
2. 按 `F5` 刷新页面 → 点"重连"
3. **期望**：回到原座位，手牌还在，房间人数不变

> 若刷新后进不去 / 变成新玩家 / 房间人数 +1 → **前后端没配套部署**，回到第 3.3 步确认 `client/build` 也已替换。

**B. 顶替尝试（必须失败）**

1. 在玩家 A 的浏览器执行 `JSON.parse(localStorage.getItem('ddz_last_connection'))`，
   把 `playerId` 抄下来（这就是攻击者能从广播里看到的公开信息）
2. 开一个新的隐身窗口，进入同一个房间号
3. **期望**：以**新玩家**身份加入（房间有多余座位时），或提示"房间已满"；
   **绝不能**顶掉玩家 A —— A 的座位、手牌、视角应完全不受影响

| # | 检查项 | 期望结果 |
|---|--------|----------|
| 14 | 刷新页面能重连回原座位 | 座位/手牌不变 |
| 15 | 广播载荷里没有 `sessionToken` | F12 搜 `sessionToken` 只在自己的 `roomCreated`/`joinedRoom` 回包里出现，`roomUpdated` 里为 `null` |
| 16 | 拿别人的 `playerId` 入房 | 只能作为新玩家加入，无法顶替 |

## 7. 已知坑（都踩过，别重复踩）

| 坑 | 现象 | 正确做法 |
|----|------|----------|
| `CI=true` 构建 | `Failed to compile. [eslint] ...` 一堆 warning 被当错误 | 构建前 `unset CI`（Windows PowerShell：`Remove-Item Env:CI`） |
| 本地 `node_modules` 一起打包 | 传了几百 MB，服务器上还跑不起来 | **永远不要**打包 `node_modules` |
| 指望 `git pull` 拿到前端 | 部署后页面还是旧版 | `client/build` 在 `.gitignore` 里，必须单独构建打包 |
| 服务器访问 GitHub | `git pull` 长时间无响应 | 用方案 A，在本地构建后上传 |
| 改了 `client/src/config.js` | 前端连不上后端，WebSocket 一直重连 | 当前**没有** `/socket.io` 反向代理，必须保持 `http://8.137.195.155:3001` |
| 正在有人打牌时重启 | 所有人掉线，对局丢失（无持久化） | 挑空闲时段；长期方案见 `docs/01` 第 7 节 |
| 部署后仍看到对手手牌 | 无痕窗口之前缓存了旧 bundle | 强制刷新 `Ctrl+F5`；或看 `index.html` 里的 `main.<hash>.js` 是否已变 |

## 8. 后续建议（本次不做，但值得排期）

1. **配置 Nginx 反向代理** —— 把 `/socket.io/` 转发到 `127.0.0.1:3001`，前端改同域相对路径，顺手关掉 3001 的公网暴露（详见 `docs/04` 第 4 节）。
2. **申请域名 + HTTPS** —— 目前是明文 `http://` + `ws://`，微信内分享会被降级（P0-5）。
3. **加持久化** —— 现在 `pm2 restart` 就丢全部对局（P0-6）。
4. **补完 `sessionToken`** —— 目前只堵死了"同名顶替"，完整会话机制还没做（P0-4）。
