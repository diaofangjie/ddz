# 02 - 通信协议规范

> 传输层：Socket.IO 4.x over WebSocket（回退 polling）。
> 本文件是前后端的**唯一契约来源**。任何事件增删改，必须先改本文件。
> 协议版本：`proto = 1`（当前实现）→ 目标 `proto = 2`（本文标注为 🎯 的条目）。

---

## 1. 通用约定

### 1.1 命名与结构

- 事件名：现状为 `camelCase`（如 `createRoom`）。**迁移期保持 `camelCase` 不改名**，避免前后端同时大改；新事件（🎯）采用 `域:动作` 冒号风格（如 `room:join`），并把旧名注册为别名逐步退役。
- 动作事件统一带 `ack` 回调：`socket.emit(event, payload, (res) => {})`。🎯 目标：**所有动作类事件都返回 ack**，`{ ok: true }` 或 `{ ok: false, code, message }`。
- 服务端广播事件不要求 ack。

### 1.2 身份（🎯 重要变更）

| 版本 | 身份来源 |
|------|----------|
| 现状 `proto=1` | 客户端在每个动作 payload 里自报 `playerId`（🔴 可伪造，见 P0-3） |
| 🎯 `proto=2` | 服务端在连接建立时签发 `sessionToken`；**所有动作 payload 不再包含 `playerId`**，服务端从 `socket.data.playerId` 取 |

**握手流程（🎯）**：

```
客户端连接 → 服务端 emit 'session:hello' { sessionToken?, proto: 2 }
  ├─ 客户端无 token：服务端签发新 token 并在 ack 中返回，客户端存 localStorage
  └─ 客户端带 token：服务端校验并恢复 playerId / 所在房间
```

**错误码表**：

| code | 含义 | 客户端处理 |
|------|------|-----------|
| `AUTH_REQUIRED` | 未完成会话握手 | 重新握手 |
| `NOT_IN_ROOM` | 不在房间内 | 回大厅 |
| `NOT_YOUR_TURN` | 没轮到你 | 忽略 + 轻提示 |
| `INVALID_ACTION` | 动作不合法（如牌型不匹配） | 提示 `message` |
| `ILLEGAL_CARDS` | 选中的牌不在手牌中 | 刷新状态 |
| `ROOM_FULL` | 房间已满（含观战席） | 提示 |
| `ROOM_NOT_FOUND` | 房间不存在或已销毁 | 回大厅 |
| `PHASE_MISMATCH` | 当前阶段不允许该动作 | 刷新状态 |
| `INTERNAL` | 服务端异常 | 上报日志 |

## 3. 服务端 → 客户端（S2C）

### 3.1 现状事件

| # | 事件名 | Payload | 说明 |
|---|--------|---------|------|
| 1 | `roomListUpdated` | `RoomListItem[]` | 大厅列表，全量 |
| 2 | `roomCreated` | `Room` | 单发创建者 |
| 3 | `joinedRoom` | `Room` | 单发加入者 |
| 4 | `leftRoom` | — | 单发 |
| 5 | `roomUpdated` | `Room` | 房间内广播（准备/换座/进出） |
| 6 | `gameStarted` | `Room` | 开局 |
| 7 | `gameUpdated` | `Room` | **🔴 高危：含所有人手牌** |
| 8 | `roundEnded` | `Room + roundSummary` | 单局结束 |
| 9 | `gameEnded` | `Room + finalSettlement` | 整场结束 |
| 10 | `messageReceived` | `Message` | 聊天 |
| 11 | `error` | `{ message }` | 通用错误 |
| 12 | `gameError` | `{ message, code }` | 对局错误 |

### 3.2 🎯 目标：收敛为统一状态事件

把 `roomUpdated` / `gameStarted` / `gameUpdated` **合并为一个** `room:state`，用 `phase` 区分含义。理由：三者在客户端都导致"重绘整个房间"，分成三个事件名只增加分支。

| # | 事件名 | Payload | 说明 |
|---|--------|---------|------|
| 1 | `session:hello` | `{ sessionToken, proto, playerId }` | 握手响应 |
| 2 | `lobby:rooms` | `RoomListItem[]` | 大厅列表（替代 `roomListUpdated`） |
| 3 | `room:state` | **投影后的 Room** | 逐人单发，**唯一的状态同步事件** |
| 4 | `room:event` | `{ type, payload }` | 轻量增量提示（`PLAY`/`PASS`/`CHAT`/`JOIN`/`LEAVE`），用于动画与音效，不承载状态 |
| 5 | `game:ended` | `{ result, settlement }` | 整场结算 |
| 6 | `error` | `{ code, message }` | 统一错误（含错误码） |

**`room:state` 投影字段规范**（详见 `01-目标架构设计.md` 第 3 节）：

```jsonc
{
  "proto": 2,
  "roomId": "AB12",
  "phase": "playing",              // waiting|dealing|calling|doubling|discarding|playing|settling
  "rules": { "mode": 3, "laizi": false, "capMultiplier": 4, "rounds": 8, "turnTimeLimit": 20 },
  "round": { "index": 3, "total": 8 },
  "seats": [
    { "index": 0, "name": "阿强", "avatar": "…", "ready": true,
      "online": true, "isBot": false, "score": 12,
      "handCount": 17,              // ← 他人只有张数
      "hand": ["S3","H3"]        ,  // ← 仅 viewer 自己有此字段
      "role": "landlord" }          // landlord|farmer|null
  ],
  "currentSeat": 1,
  "turnDeadlineAt": 1757923200000,  // 绝对时间戳，客户端自行倒计时（避免时钟漂移累积）
  "bottomCards": null,              // 抢地主结束前为 null
  "lastPlay": { "seat": 1, "cards": ["S5","S6"], "combo": "straight" },
  "playedCount": [17, 12, 15],       // 已出牌张数（记牌器用）
  "scores": { "round": [3,-1,-2], "total": [12,4,-16] },
  "spectators": 2,
  "capacity": 10
}
```

> **时区/时钟注意**：统一用**服务端绝对时间戳** + 客户端本地计算剩余秒数。不要下发"剩余 20 秒"这种相对值 —— 网络延迟会让倒计时各端不一致。

## 4. 调试与自测脚本

协议验证应可通过纯脚本完成（不依赖浏览器）：

```js
// server/test/protocol.e2e.js（示意）
import { io } from 'socket.io-client';
const URL = process.env.URL || 'http://localhost:3001';

// 场景：3 人开局 → 断言每人的 hand 只包含自己的牌
const clients = await Promise.all([1,2,3].map(() => connect(URL)));
// ... 走完 createRoom / joinRoom / startGame，收集每个人收到的 room:state
// 断言：client[i].lastState.seats.filter(s => s.hand).length === 1
```

**核心断言（每条都是回归防线）**：

| 编号 | 断言 | 防的是什么 |
|------|------|-----------|
| P-01 | 任一客户端收到的状态中，带 `hand` 字段的座位数恒为 1 | P0-2 手牌泄露 |
| P-02 | 非本人身份的 `playCards` 被拒绝且返回 `NOT_YOUR_TURN` | P0-3 身份伪造 |
| P-03 | 篡改 `playerId` 无效（字段已不存在） | P0-3 |
| P-04 | 同一房间所有客户端收到的状态为同一 `rev` 版本号 | 广播不一致 (P1-1) |
| P-05 | 4 个客户端同房，座位满后第 4 个进观战席，其状态中无任何 `hand` | 观战者隔离 |
| P-06 | 断线 30s 内凭 token 重连，`hand` 与断线前逐张一致 | 重连正确性 |
| P-07 | 轮到 NPC 时，2s 内自动产生一次合法动作 | 托管可用 |
| P-08 | 回合计时到点后自动 pass/出最小牌，且阶段正确推进 | 超时逻辑 (P1-3) |
